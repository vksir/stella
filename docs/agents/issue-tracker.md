# Issue tracker: Local Markdown

Issues and specs for this repo live as Markdown files under `.scratch/`.

## Conventions

- Feature specs may be stored directly as `.scratch/<feature-slug>.md`.
- Keep existing files in place; do not relocate or reformat them as part of tracker setup.
- Record the issue status near the top of each file when applicable, using the project's triage role strings.
- Append relevant discussion under a `## Comments` heading.

## When a skill says "publish to the issue tracker"

Create or update a Markdown file under `.scratch/`. Use the feature slug in the filename and follow the existing file's format.

## When a skill says "fetch the relevant ticket"

Read the referenced file under `.scratch/`. The user will normally pass the path or issue identifier directly.
